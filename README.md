# Runforge - Runs Dashboard (Test Task)

## Установка и запуск

1. `npm install`
2. `npm run dev`
3. Откройте `http://localhost:5173`

## Технологии

- React (Vite)
- TypeScript
- CSS

## Структура проекта

- `src/api/mockApi.ts` — мок-сервис с данными (имитация задержки сети и ошибки).
- `src/components` — UI-компоненты (Список, Карточка, Фильтры, Модалка, Лоадер).
- `src/App.tsx` — основная логика: стейт, фильтрация, поиск.

## Проверка сценариев (ручное тестирование)

Так как я пока не писал автотесты, я проверил основные сценарии вручную, имитируя действия пользователя.

**Обратите внимание:** в `mockApi.ts` я специально настроил имитацию сетевой ошибки при **самом первом** запросе, чтобы сразу продемонстрировать работу состояния ошибки (Error state). 

Вот как проверяются все сценарии:

1. **Ошибка и её обработка:** При первом открытии страницы (или после перезагрузки) появится сообщение об ошибке и кнопка «Повторить». Это срабатывает искусственно заданный сбой.
2. **Загрузка (Retry):** При нажатии на кнопку «Повторить» происходит повторный запрос к мок-сервису. Появляется спиннер загрузки (добавлена искусственная задержка 1.2 сек), после чего успешно отрисовывается список запусков.
3. **Поиск и фильтры:**
   - Ввожу "web" в поиск — список сужается до запусков с репозиторием web-platform.
   - Нажимаю "Failed" — остаются только упавшие запуски.
   - Поиск и фильтр работают вместе.
4. **Пустой результат:** Ввожу "asdasd" — появляется сообщение "Ничего не найдено" и кнопка "Сбросить фильтры", которая очищает поиск и возвращает список.
5. **Детали:** Клик по любой карточке открывает модальное окно с логами и результатом (если он есть). Закрывается по крестику или клику по фону.
6. **Адаптивность:** Проверил в DevTools на ширине 360px — карточки перестраиваются в колонку, текст не вылезает за границы.
